# 数据获取说明（data-source）

> 本文档描述平台**需要哪些数据**、为什么需要，以及如何获取的通用思路。
> 刻意不标注具体接口/字段细节——接入新项目或更换数据源时可替换参考地址而不改内容。
> 具体查询语法、字段名见源码 `compose-db.js`。

## 构建流程

离线执行构建命令（见 `package.json` 的 `compose-db`），抓取数据并生成
`out/${owner}.${repo}.data.json`，前端静态加载该文件。

- 需要认证（token），通过环境变量或 `.env` 提供。
- 每次构建生成一份快照；前端不实时请求上游。

## 需要的数据（按用途）

| 用途 | 需要的数据 | 得到什么 |
|---|---|---|
| PR 列表与卡片 | 目标仓库所有**开放的** PR | 标题、号、作者、草稿标记、里程碑、目标分支、创建/更新时间 |
| 文件归组 | 每个 PR 改动的文件及其变更类型（新增/修改/删除/重命名） | 用于按路径聚合展示 |
| 文件树 | 目标分支的**完整文件系统快照** | 展示可浏览的目录树 |
| 近期看板 | 最近 1 周**未合并被关闭**的 PR | 单独区块展示，计入关闭计数 |
| 作者信息 | 作者标识、头像、其开放 PR 数 | 卡片作者块与高亮 |
| 元数据 | 生成时间戳 | 页面"生成于 X 前" |

## 关键约束（务必要知道）

- **文件树是快照**：它只反映目标分支当前已存在的文件，**不包含**任何 PR 中"未合并"的新增文件。因此新增、删除、重命名的文件需结合 PR 的变更数据才能完整展示。
- **近期关闭 PR 需按时间过滤**：平台的"近期"看板依赖"按关闭时间筛选"的能力，但常规的 PR 列表接口不提供该能力；必须借助上游的**搜索/查询**能力按时间精确筛选，而非拉全量历史。
- **开放 PR 分页**：开放的 PR 可能较多，需分页逐页抓取；分页按游标推进。

## 参考文档地址

> 换用其他数据源（如 GitLab、Gitea、自建 API）时，仅需替换这里的参考链接，
> 并让 `compose-db.js` 适配对应数据源的"开放 PR / 变更文件 / 文件树 / 按时间搜索"能力。

- GitHub 官方接口文档（数据获取主参考）：https://docs.github.com/en/rest
- 项目源码（具体实现）：`compose-db.js`

## 接入新项目时需替换

1. 目标仓库 `owner/repo`。
2. 认证方式与 token。
3. 分支命名约定（主/发布/反向移植分支）。
4. 上述参考文档地址（若数据源非 GitHub）。
