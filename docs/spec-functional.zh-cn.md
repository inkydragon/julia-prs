# 功能规格（Functional Spec）

> 本文档描述**本模板平台**的功能能力，作为任意项目接入后的功能验收基准。
> 每条功能给出**通用定义**，并用具体项目（本案为 JuliaLang/julia）举例说明。
> 区分"功能"（做什么）与"UI 设计"（如何呈现）——UI 见 `docs/design-ui.md`。

## 概述

本平台是一个纯静态站点：离线抓取目标开源仓库的开放 PR（pull request）数据，
生成 JSON 数据文件，由浏览器静态加载，展示"按文件/文件夹归组、可检索、可定位"
的开放 PR 列表。

核心价值：帮助仓库贡献者快速找到"修改了某个文件/文件夹的开放 PR"。

> 举例：本案例接入 `JuliaLang/julia`，平台即用于展示该仓库所有开放 PR 及其修改的文件。

## 数据源与构建

- 数据来源：目标仓库的 PR 相关 API（GraphQL 拉取开放 PR、REST 拉取仓库文件树）。
- 构建命令：`yarn compose-db`，产出 `out/${owner}.${repo}.data.json`。
- 认证：`GRAPHQL_TOKEN` / `GITHUB_TOKEN`（环境变量或 `.env`）。
- 输出 schema（与具体仓库无关）：
  - `generated_at`：生成时间戳
  - `authors`：作者映射（id → 作者信息 + 其开放 PR 数）
  - `pulls`：开放 PR 数组
  - `branches`：所有目标分支名
  - `files`：按分支组织的文件树条目

> 举例：本案例输出 `out/JuliaLang.julia.data.json`，其中 `pulls` 含 989 条开放 PR。

## 功能清单（通用能力）

### 1. 分支管理
- **F-1.1 列出可选分支**：展示所有指向目标分支的开放 PR 的目标分支名。
- **F-1.2 分支排序**：主分支置顶 → 发布分支（按版本号倒序）→ 反向移植分支（按版本号倒序）→ 其他分支最后。
- **F-1.3 切换分支**：切换后重置到根目录，并持久化该仓库的选中分支。
- **F-1.4 分支选择器**：下拉列表切换；当前分支高亮。
- **F-1.5 无文件树分支兜底**：某分支若抓取文件树失败，则不出现在列表中。

> 举例（本案例命名约定）：主分支为 `master`；发布分支为 `release-1.11` 样式；
> 反向移植为 `backports-release-1.11`；个人/实验分支如 `vc/llvm-dialects-tablegen` 排最后。
> 接入其他仓库时可定义不同的"主/发布/反向移植"分支命名，映射到对应的排序优先级。

### 2. 文件树浏览
- **F-2.1 文件/文件夹分层**：PR 改动文件会在其所有父目录层级也出现，便于按目录聚合。
- **F-2.2 文件夹优先排序**：同目录下，文件夹排在文件之前，其余按路径字母序。
- **F-2.3 展开/折叠**：点击图标切换文件夹展开/折叠；点击文件夹名称做路径选择。
- **F-2.4 根节点重置**：点击根节点图标返回根目录。
- **F-2.5 PR 计数**：每个条目显示命中该路径的开放 PR 数量。
- **F-2.6 已选路径高亮**：当前选中路径的条目高亮。
- **F-2.7 过滤联动**：设置了 PR 号过滤时，文件树只保留含该 PR 的路径。
- **F-2.8 变更状态标记**：当精确定位到某个 PR 时，左侧文件树对该 PR 涉及的条目以颜色/图标区分变更类型——新增（ADDED）、修改（MODIFIED）、删除（DELETED）、重命名/移动（RENAMED）。非该 PR 的条目不标记。
  - 标记来源：PR 数据中的 `files[].changeType`（已存在），而非文件树快照。
  - 差异说明：新增/删除/重命名（新路径以外）文件不在文件树快照中，标记时需合并 PR 的变更数据才能显示。

> 举例：一个 PR 改动 `src/foo.jl`，平台会自动在 `src`、`src/foo.jl` 两个层级的节点都
> 出现该 PR，因此浏览到目录 `src` 或文件 `src/foo.jl` 都能看到它。
> 当精确定位到该 PR 时，`src/foo.jl` 会显示其变更状态（如新增标识）。

### 3. PR 列表
- **F-3.1 按路径过滤**：右侧 PR 列表只显示所选路径（含父目录聚合）相关的 PR。
- **F-3.2 按分支过滤**：只显示目标分支为当前选中分支的 PR。
- **F-3.3 PR 排序**：按 PR 号降序。
- **F-3.4 仅显示命中 PR**（过滤模式）：输入 PR 号时只显示该 PR 一张卡片。

### 4. PR 搜索定位
- **F-4.1 输入识别**：支持三类输入——PR 链接、`owner/repo#号`、纯数字 PR 号。
- **F-4.2 自动定位**：搜索到 PR 时自动切到其目标分支，并选中其首个存在于文件树的文件路径，渲染 PR 卡片；PR 不存在则保持当前分支/路径不变。
- **F-4.3 新增文件兜底**：PR 仅涉新增文件（不在文件树快照中）时，仍保证 PR 卡片可渲染。
- **F-4.4 变更状态呈现**：精确定位后，文件树对该 PR 涉及条目显示变更状态标记（见 F-2.8）。

> 举例：输入 `62938`（或对应链接），自动跳转到其目标分支 `vc/llvm-dialects-tablegen`
> 并选中首个存在的文件 `src/Makefile`，渲染该 PR 卡片。

### 5. PR 卡片信息
- **F-5.1 基本信息**：PR 号、标题、对上游链接、草稿标记。
- **F-5.2 作者**：作者链接、作者开放 PR 数（高量级作者高亮、异常作者特殊标记）。
- **F-5.3 详情**：目标分支、里程碑、diff/patch 链接。
- **F-5.4 时间**：创建、更新日期（悬停含精确时间戳）。
- **F-5.5 开放时长**：自动换算为天/周/月/年。

### 6. 仓库与状态
- **F-6.1 仓库切换**：列出所有可用仓库并切换（切换后整页刷新）。
- **F-6.2 URL 状态同步**：仓库/分支/路径/PR/作者/生成时间通过 URL 查询参数同步，可分享、可回退。
- **F-6.3 本地偏好持久化**：记住选中仓库、各仓库的选中分支（localStorage）。
- **F-6.4 生成时间展示**：显示数据生成时间。

## 非功能性约束

- **纯静态**：无后端、无运行时服务，部署即静态目录（如 `out/`）。
- **低维护**：构建链简单、依赖少。
- **多仓库可扩展**：数据文件按 `owner.repo.data.json` 命名；可用仓库列表与各仓库约定的分支命名集中化配置。

## 接入新项目的差异点

接入任意仓库时，功能定义不变，仅需替换/配置：
1. 数据源仓库（owner/repo 及认证 token）。
2. 分支命名约定（主/发布/反向移植分支的映射规则，见 F-1.2）。
3. 可用仓库列表（见 F-6.1）。
4. 展示文案中的仓库名/链接（见 UI 文档）。
